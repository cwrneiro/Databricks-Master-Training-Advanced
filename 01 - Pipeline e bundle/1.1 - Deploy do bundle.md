# 1.1 - Deploy do bundle

Nesta parte, você abre o bundle, coloca o seu nome nele e faz o primeiro deploy, em `dev`.

## O que está no bundle

```
01 - Pipeline e bundle/
├── databricks.yml                  # nome do bundle, variáveis e targets dev/prod
├── resources/
│   ├── aluno.schema.yml            # o seu schema: academydb.<aluno>
│   ├── autorizacoes.pipeline.yml   # o pipeline (serverless)
│   └── autorizacoes.job.yml        # o job: pipeline → validar, a cada 10 min
└── src/
    ├── pipeline/
    │   ├── bronze.py               # bronze_autorizacao_eventos (Auto Loader)
    │   ├── silver.py               # eventos_validos + silver_autorizacao_status
    │   ├── gold.py                 # gold_kpi_autorizacoes (materialized view)
    │   └── notificacoes.py         # notif_autorizacao_negada (foreach_batch_sink)
    └── validar.py                  # notebook com os asserts da segunda task do job
```

---

## Passo 1: Ver o primeiro lote

Antes de mexer no código, veja os dados que o pipeline vai ler.

1. No menu lateral, clique em **Catalog**
2. Abra `academydb` → `shared` → **Volumes** → `raw` → `autorizacao_eventos`
3. Abra o arquivo `lote_001.json`

Repare que há um evento por linha, e procure uma duplicata ou um status estranho: o pipeline vai ter que lidar com os dois.

## Passo 2: Clonar o repo como Git folder

1. No menu lateral, clique em **Workspace** → **Create** → **Git folder**
2. Cole a URL do repo que o instrutor passar. A versão pública é:
```
https://github.com/cwrneiro/Databricks-Master-Training-Advanced
```
3. Clique em **Create Git folder**

## Passo 3: Abrir o bundle

1. Na Git folder, abra a pasta `01 - Pipeline e bundle`
2. Clique em `databricks.yml`

Repare que o workspace reconhece a pasta como um bundle. Clique em **Deployments** ao lado do editor. É nele que você faz os deploys do dia.

## Passo 4: Explorar a estrutura
> DABs: Estrutura de um projeto

Cada arquivo e diretório do bundle tem uma função:

```
├── databricks.yml
```

O `databricks.yml` é o ponto de entrada do bundle.

```
├── resources/
│   ├── aluno.schema.yml
│   ├── autorizacoes.pipeline.yml
│   └── autorizacoes.job.yml
```

O subdiretório `resources/` guarda as declarações dos recursos do bundle.

```
└── src/
    ├── pipeline/
    │   ├── bronze.py
    │   ├── silver.py
    │   ├── gold.py
    │   └── notificacoes.py
    └── validar.py
```

E no subdiretório `src/` ficam os outros arquivos importantes (Python, SQL...).

Vamos explorar a estrutura:
1. Navegue até `src/pipeline/` e abra o arquivo `bronze.py`
2. Repare na estrutura das pipelines declarativas:
    - Expectations
    - Autoloader
3. Veja o equivalente escrito usando a estratégia de `MERGE` usando Structured Streaming puro

## Passo 5: Preencher o seu nome de aluno

O seu nome de aluno é a primeira letra do nome + o sobrenome, sem acento e em minúsculas (ex.: Augusto Carneiro → `acarneiro`). Ele vira o seu schema (`academydb.acarneiro`) e entra no nome de tudo o que você cria.

1. Em `databricks.yml`, procure a linha marcada com `# TODO (passo 5)`
2. Troque `troque_pelo_seu_nome` pelo seu nome de aluno:
```yaml
  aluno:
    ...
    default: acarneiro
```

> Se alguém da turma já tiver o mesmo nome, acrescente um número (`acarneiro2`).

## Passo 6: Deploy em `dev`

1. No painel **Deployments**, deixe o target `dev` selecionado
2. Clique em **Deploy**
3. Confira o que o diálogo lista e confirme:
    - o schema `dev_<usuario>_<aluno>`
    - o pipeline e o job, com o prefixo `[dev <usuario>]`

Repare nos prefixos: o `mode: development` do target `dev` os coloca para que o seu teste nunca esbarre no de outra pessoa, e ainda pausa o schedule do job.
