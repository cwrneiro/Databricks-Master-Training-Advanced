3.3 - Deploy do agente

Nesta parte, você declara o model service, publica o agente pronto do repo e dá a ele acesso ao que ele usa.

Passo 4: Model service

O model service é um nome seu no AI Gateway para o Claude, e também entra no bundle.

  1. Em 01 - Pipeline e bundle/resources/, clique em Create → File e dê o nome llm.model_service.yml
  2. Cole: 
    resources:
  model_services:
    llm:
      # academydb.<aluno>.llm: um nome seu no AI Gateway para o Claude do system.ai.
      parent: schemas/${var.catalog}.${resources.schemas.aluno.name}
      model_service_id: llm
      config:
        routing:
          destinations:
            - destination_type: DESTINATION_TYPE_PAY_PER_TOKEN_FOUNDATION_MODEL
              name: system.ai.databricks-claude-sonnet-4-5
              pay_per_token_config:
                model: models/system.ai.databricks-claude-sonnet-4-5
              traffic_percentage: 100
  3. No painel Deployments, com o target prod, clique em Deploy
💡 Por que um model service, e não o modelo do system.ai direto

O app do agente roda com uma identidade própria, que precisa de permissão para chamar o modelo. No system.ai, só o admin concede. O academydb.<aluno>.llm é seu, e você mesmo concede (passo 7).

Ele também é o lugar onde, no dia a dia, você trocaria de modelo ou poria limites de uso sem mexer no agente.

Passo 5: Ler o agente

O agente já vem pronto em 03 - Agente/agente/: é um projeto do Agent Runtime (agentbricks), com LangChain. Abra os arquivos que importam:

Arquivo O que tem
agent/agent.py ALUNO e MODEL (o seu model service), o prompt de sistema e create_agent_graph, que junta o modelo e as tools
agent/mcps.py A busca no seu índice documentos_idx, oferecida ao agente como tool pelo MCP do AI Search
agent.toml As lojas de sessões e de memória, o experimento de tracing e, depois do passo 6, a tool da Genie

Repare que o modelo decide sozinho qual tool chamar. O prompt de sistema só dá a regra: documentos para regras e prazos, Genie para números.

Passo 6: Deploy do agente pelo web terminal

  1. No notebook_agente.py, rode a seção 2. Ela imprime os comandos já com o caminho da sua pasta e o seu nome
  2. Abra o web terminal: no painel inferior do notebook, clique em Terminal
  3. Cole os comandos, trocando <id do Genie space> pelo ID que você copiou no passo 3: 
    pip install databricks-agentbricks==0.5.1
cd "/Workspace/Users/<seu e-mail>/<repo>/03 - Agente/agente"
sed -i 's/troque_pelo_seu_nome/<aluno>/g' agent.toml agent/agent.py
agentbricks tools add genie-agent <id do Genie space>
agentbricks deploy <aluno>

O deploy leva ~3 min. Um redeploy leva ~40 s.

O agente fica fora do bundle: o agentbricks deploy cria peças (as lojas e o Runtime Store) que o bundle ainda não sabe declarar.

💡 O que cada comando faz
  • O sed põe o seu nome em agent/agent.py (ALUNO) e nas lojas do agent.toml.
  • O tools add grava a Genie no agent.toml com auth = "user": a Genie roda como quem conversa com o agente, com as permissões dessa pessoa nas tabelas.
  • O deploy cria o app agent-bricks-<aluno>, as lojas de sessões e de memória e o experimento de tracing, e sobe o código.

Passo 7: Dar acesso ao app do agente

Se você abrir o app agora, a primeira pergunta falha com este erro:

agent invocation failed

O service principal (SP) do app ainda não tem permissão no seu model service nem no seu índice. Vamos conceder pelo bundle.

  1. Rode a seção 3 do notebook e copie o application ID do SP
  2. Em databricks.yml, dentro de variables:, cole a variável agent_sp, com o ID no default: 
      agent_sp:
    description: Application ID do service principal do app do seu agente (agent-bricks-<aluno>).
    default: 00000000-0000-0000-0000-000000000000 # o ID que a seção 3 mostrou
  3. No fim de resources/aluno.schema.yml, alinhado com comment:, cole: 
          grants:
        - principal: ${var.agent_sp}
          privileges: [USE_SCHEMA, SELECT]
  4. No fim de resources/llm.model_service.yml, alinhado com config:, cole: 
          grants:
        - principal: ${var.agent_sp}
          privileges: [EXECUTE]
  5. Deploy em prod
  6. Rode o checkpoint do notebook. Ele fica verde
👉 Resultado esperado: 
✅ O app agent-bricks-<aluno> pode usar o índice e o model service. Abra <url> e converse com o agente.

Repare que o SELECT no schema cobre o índice, que mora nele. O USE CATALOG no academydb o SP já tem: o setup deu a todos os usuários da conta.

Os grants ficam declarados junto com os recursos: um deploy em outro workspace leva as permissões junto.
