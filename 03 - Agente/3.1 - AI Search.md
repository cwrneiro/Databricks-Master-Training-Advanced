# 3.1 - AI Search

Nesta parte, você leva os PDFs para uma tabela de trechos, dentro do seu pipeline, e cria o índice de AI Search sobre ela.

## Passo 1: Trechos dos documentos
> Declarative Pipelines · AI Functions: ai_parse_document · Bundles

Os trechos entram no mesmo pipeline do módulo 1, em SQL: um pipeline aceita Python e SQL juntos.

1. Na Git folder, abra a pasta `01 - Pipeline e bundle/src/pipeline/`
2. Clique em **Create → File** e dê o nome `documentos.sql`
3. Cole:
```sql
-- Trechos dos documentos da operadora (PDFs), a fonte do índice de AI Search do agente.
-- Streaming table: cada PDF novo é lido uma vez só, e os runs seguintes do job não reprocessam nada.
CREATE OR REFRESH STREAMING TABLE documentos_chunks (
  CONSTRAINT texto_presente EXPECT (texto IS NOT NULL AND texto <> '') ON VIOLATION DROP ROW
)
COMMENT 'Trechos dos documentos da operadora, um por bloco de texto. Fonte do índice de AI Search.'
TBLPROPERTIES ('delta.enableChangeDataFeed' = 'true')
AS
WITH documentos AS (
  -- ai_parse_document lê o PDF e devolve os blocos (títulos, parágrafos, rodapés...) com o tipo de cada um.
  SELECT _metadata.file_name AS documento, ai_parse_document(content, map('version', '2.0')) AS parsed
  FROM STREAM read_files('/Volumes/${catalog}/shared/raw/docs/', format => 'binaryFile')
)
SELECT
  concat(documento, '-', e.pos) AS chunk_id,
  documento,
  e.value:content::string AS texto
FROM documentos, LATERAL variant_explode(parsed:document:elements) AS e
-- Fica só o texto corrido: cabeçalhos, rodapés e números de página não ajudam a responder perguntas.
WHERE e.value:type::string = 'text'
```
4. No painel **Deployments**, com o target `prod`, clique em **Deploy**
5. Clique em **Run job** (~3 min)

> Lembre-se: em `prod`, código novo só vale depois de deploy.

<details markdown="1">
<summary>💡 Como o <code>documentos.sql</code> funciona</summary>

- O pipeline lê todos os arquivos de `src/pipeline/`, então o arquivo novo já faz parte dele.
- `${catalog}` vem do `configuration` do pipeline, o mesmo que o Python lê com `spark.conf.get`.
- O Change Data Feed é o que o índice lê para acompanhar a tabela, como a synced table do módulo 2 faz com a silver.
- O `ai_parse_document` fica no `WITH`, e não dentro do `LATERAL`: o Spark não aceita uma função não determinística (cada chamada ao modelo pode responder diferente) dentro de um `LATERAL`.

</details>

## Passo 2: Índice de AI Search
> AI Search · Bundles

O índice lê a `documentos_chunks`, que o run do passo 1 criou.

1. Em `01 - Pipeline e bundle/resources/`, clique em **Create → File** e dê o nome `documentos.index.yml`
2. Cole:
```yaml
resources:
  vector_search_indexes:
    documentos:
      name: ${var.catalog}.${resources.schemas.aluno.name}.documentos_idx
      endpoint_name: edia-ai-search-1 # endpoint do instrutor; troque só se ele indicar outro
      primary_key: chunk_id
      # Delta Sync: o índice acompanha a tabela pelo Change Data Feed.
      index_type: DELTA_SYNC
      delta_sync_index_spec:
        source_table: ${var.catalog}.${resources.schemas.aluno.name}.documentos_chunks
        pipeline_type: TRIGGERED
        # O AI Search calcula o embedding de cada trecho com este modelo, que entende português.
        embedding_source_columns:
          - name: texto
            embedding_model_endpoint_name: databricks-qwen3-embedding-0-6b
```
3. **Deploy** em `prod` (~40 s). O índice fica pronto ~1 min depois

Agora, confira o índice:

1. Abra `03 - Agente/notebook_agente.py`
2. Conecte no **serverless** e preencha o widget `aluno`
3. Rode a **seção 1**

Ela confere o índice e faz a busca que o agente vai fazer. Repare que a pergunta sobre ressonância devolve primeiro os trechos com "21 dias úteis".
