# 2.1 - Synced table no bundle

Nesta parte, você declara a synced table no bundle e faz o job sincronizá-la a cada run.

## Passo 1: Declarar a synced table no bundle
> Lakebase: Synced tables · Delta: Change Data Feed · Bundles

1. Na Git folder, abra a pasta `01 - Pipeline e bundle/resources/`
2. Clique em **Create → File** e dê o nome `autorizacao_status.synced_table.yml`
3. Cole:
```yaml
resources:
  postgres_synced_tables:
    autorizacao_status:
      # Nome no Unity Catalog. No Postgres, vira a tabela autorizacao_status no schema <aluno>.
      synced_table_id: ${var.catalog}.${resources.schemas.aluno.name}.autorizacao_status
      source_table_full_name: ${var.catalog}.${resources.schemas.aluno.name}.silver_autorizacao_status
      primary_key_columns:
        - autorizacao_id
      # Triggered: sincroniza só quando alguém dispara (a task sync_lakebase do job).
      scheduling_policy: TRIGGERED
      branch: projects/edia-workshop/branches/production # projeto Lakebase do instrutor; não mude
      postgres_database: databricks_postgres
      create_database_objects_if_missing: true
      new_pipeline_spec:
        storage_catalog: ${var.catalog}
        storage_schema: ${resources.schemas.aluno.name}
```

Repare que você não precisou mexer no `databricks.yml`: ele inclui `resources/*.yml`, então o arquivo novo já faz parte do bundle.

<details markdown="1">
<summary>💡 O que cada parte do YAML faz</summary>

- `source_table_full_name`: a origem, a sua silver. O sync incremental lê o *Change Data Feed* dela, que o `delta.enableChangeDataFeed` do módulo 1 ligou.
- `primary_key_columns`: a chave da tabela no Postgres. A silver tem uma linha por `autorizacao_id` desde o `AUTO CDC`.
- `create_database_objects_if_missing`: cria o schema Postgres `<aluno>` no primeiro sync.
- `new_pipeline_spec`: o sync roda num pipeline gerenciado, criado junto com a synced table.

</details>

## Passo 2: Sincronizar a cada run do job
> Jobs: Pipeline task

Uma synced table *Triggered* só copia as mudanças quando alguém dispara o pipeline dela. Vamos fazer o job disparar, logo depois da `validar`.

1. Abra `resources/autorizacoes.job.yml`
2. No fim da lista `tasks:`, cole a terceira task:
```yaml
        - task_key: sync_lakebase
          depends_on:
            - task_key: validar
          pipeline_task:
            pipeline_id: ${resources.postgres_synced_tables.autorizacao_status.status.pipeline_id}
```

Repare no `depends_on: validar`, e não só no `pipeline`: se a validação ficar vermelha, o sync não roda, e o app nunca recebe dados que falharam nos `assert`s.

## Passo 3: Deploy em `prod`
> Bundles

No painel **Deployments**, com o target `prod`, clique em **Deploy** (~20 s). O deploy cria a synced table e faz a primeira carga, em menos de 1 min.

> Você mudou só YAML, mas em `prod` qualquer mudança (YAML ou código) só vale depois de um deploy em `prod`.

## Passo 4: Rodar o job
> Jobs · Lakebase: Synced tables

1. Clique em **Run job** na lista **Bundle resources**
2. Abra o Job clicando no nome dele da lista
3. Aguarde a run completar

O Jobs em `prod` está com um schedule de 10 min, desta forma nossas tabelas e o Postgres acompanham os lotes que chegam.

## Passo 5: Explorar no catálogo
> Unity Catalog · Lakebase: Synced tables

Vamos explorar no catálogo as synced tables que declaramos e populamos.

1. Abra o catálogo clicando no menu à esquerda
2. Navegue até seu schema em `academydb` → `<aluno>`
3. Veja a **Synced table** criada, `autorizacao_status`. Clique nela
4. Repare nas seguintes coisas:
- Source table
- Type
- Data source

---

<details markdown="1">
<summary>💡 Triggered, Continuous ou Snapshot</summary>

- **Snapshot**: copia a tabela inteira a cada sync. Serve para tabelas pequenas ou que mudam quase toda a cada carga.
- **Triggered** (o que você usou): copia só as mudanças, quando alguém dispara. Aqui, a task do job, logo depois de cada lote.
- **Continuous**: um pipeline sempre ligado copia as mudanças em segundos. É o que você usaria se o app precisasse do status quase em tempo real, mas ele fica ligado (e cobrando) o tempo todo.

</details>
